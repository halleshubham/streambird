# Frontend (`web-app/`)

Paths below are relative to `web-app/` unless they start with another top-level folder.

React 19 + react-router 7 + Vite + TypeScript, no UI framework, icons from `lucide-react`. One global stylesheet. Built into `dist-web/` and served by the Nest app, so the SPA and API share one origin.

### Routes (`App.tsx`)
- Public (search metadata and prerender: see "SEO" below): `/` (`HomeRoute`: anonymous → `LandingPage`, signed in → `/dashboard`), `/delete-account` (how to delete an account, linked from footers, login, privacy), `/account-deleted`, `/login`, `/signup-company`, `/privacy`, `/terms`, `/join/:token` (guest, no account), `/admin/login`, `*` → `NotFoundPage`.
- Signed in (`ProtectedRoute`; unapproved non-superadmin → `PendingApprovalPage`): `/dashboard`, `/connections`, `/billing`, `/account` (details + Delete account danger card, `DeleteAccountModal`), `/streams/new`, `/streams/upcoming`, `/streams/:id`, `/team` inside `AppShell`; **`/streams/:id/studio` is deliberately outside `AppShell`** (no nav bar).
- Superadmin (`SuperadminRoute` → `AdminShell`): `/admin`, `/analytics`, `/users`, `/accounts`, `/accounts/:id`, `/plans`, `/billing`, `/audit-log`. Add admin pages as siblings there.
- Real API routes always live under `/api` (the SPA fallback serves `index.html` for every other GET). Exception: the public permanent live link `/stream/<slug>` is a backend redirect, so never add an SPA route under `/stream/`. The Connections page shows it per YouTube/Facebook connection (`LiveLink` in `ConnectionsPage.tsx`: `data-testid="live-link"`, button `aria-label="Copy live link for <name>"`, text becomes "Copied"). Dev: Vite proxies `/api` and `/socket.io` to `localhost:3000`.

## Conventions
- **Data**: call `src/api/*`; errors are `ApiError` → show `e instanceof ApiError ? e.message : 'fallback'` in `<p className="error">`. A 204 resolves `undefined`.
- **Page states**: loading → `BirdLoader`; error → `.error`; empty → a short paragraph, ideally with a `chip-link` action.
- **Icon-only or shortened buttons keep a full `aria-label`** (tests and screen readers use it): see the selector contract in `testing.md`.
- TS is strict: `verbatimModuleSyntax` (use `import type`), `erasableSyntaxOnly` (no enums/parameter properties), `noUnusedLocals/Parameters` — unused imports **fail the build** (`tsc -b`). Lint is `oxlint` (`npm run lint --prefix web-app`; `react/rules-of-hooks` is an error, a few existing warnings are known).
- Do not add a UI/CSS framework. Do not introduce state libraries; hooks + context is the pattern.

## Styling (`src/index.css`, ~2400 lines, single file)
- Theme = CSS variables on `:root` (new token names below; the legacy `--text --text-h --card-bg --border --accent --accent-hover --error --warning` still exist and map onto them). Dark mode is **only** `@media (prefers-color-scheme: dark)` overriding those variables — always use variables, never raw colours, for anything that must work in both.
- Class names are plain kebab-case with BEM-ish `--modifier`. Shared blocks: `.panel`, `.icon-btn(--small|--accent|--danger)`, `.chip-link(--sm|--lg)`, `.segmented`, `.checkbox-row`, `.field-hint`, `.docs-hint`, `.error`, `.success`.
- The newest additions live in the "UI polish" block near the end of the file (chips, segmented control, busy overlay, studio top bar, slide controls). Add new feature CSS next to the related existing rules, or append a clearly commented block.
- **Pitfalls**
  1. A bare `input, textarea, select { width:100%; padding; margin-bottom }` rule applies to *every* control. Checkboxes/radios are re-reset; any other inline control (file, number, small select) needs explicit `width/margin/padding`. This is what once misaligned the "Require a password" checkbox.
  2. `.landing-section--alt > * { max-width:1100px; margin-left/right:auto }` beats single-class margin rules. Use `margin: X auto Y` on children there, or they sit off-centre (this broke the currency switch).
  3. Global `button` styling is the accent-filled look; a "plain" button must override background/border/colour **and** their `:hover:not(:disabled)` state.
  4. A `<label>` is `display:block; font-weight:600` globally — a label used as a button needs its own class (`label.slide-add-btn`).
  5. Sticky/fixed elements: the studio top bar is sticky only above 720 px wide; it is three rows tall on phones (there it is `position: relative; z-index: 30` so its popovers, e.g. invite password and camera/mic, stay above the picture; `.studio-invite-group` / `.studio-devices-group` are `static` so the popover spans the bar). The camera/mic popover reuses `.studio-popover`; its rows are `.studio-device-row`.
- Verify layout changes with screenshots at ~1366×800 and 390×800 (skill `streambird-ui-change`).

### Components (`import { ... } from '../components/ui'`; all classes are `ui-*`, no collisions with legacy `.badge/.panel/.chip-link`)
| Component | Props / API |
|---|---|
| `Button` | `variant` primary \| secondary \| ghost \| danger \| live (default primary), `size` sm \| md \| lg, `busy` (shows the bird, disables, `aria-busy`), `block`, `icon`; plain `<button>` props. `buttonClass(variant,size,extra)` gives the same look to a `<Link>`/`<a>`. One primary per screen; `danger` only behind `confirm()`; `live` only for Go live. Min height 44px. |
| `Field`, `Input`, `TextArea`, `SelectField` | `label`, `hint`, `error` (aria-invalid + `role=alert` message, ids wired), plus normal control props. `Field` takes a render function for any custom control. The label is a real `<label for>`. |
| `Chip` | toggle pill: `selected` (filled, `aria-pressed`), `outline`. |
| `Badge` | `tone` live \| scheduled \| ended \| success \| warning \| neutral \| pro, `dot`. |
| `Card` (alias `Panel`) | `tone` plain \| soft \| hero (gradient: hero and the primary feature card only), `compact`, `as`. |
| `Modal`, `Drawer`, `BottomSheet` | `open`, `onClose`, `title` (the accessible name), `description`, `role` dialog \| alertdialog, `footer`, `initialFocus`, `hideTitle`, `testId`. Portal to body, `aria-modal`, focus moves in and returns to the opener, Tab trapped, Esc closes, scroll locked. A scrim click closes a plain dialog, never an alertdialog. |
| `confirm(opts)` / `useConfirm()` | `await confirm({ title, body?, details?, confirmLabel?, cancelLabel?, destructive?, typeToConfirm?, typeToConfirmLabel? }) : Promise<boolean>`. Backed by `ConfirmProvider` (mounted in `main.tsx`, queues overlapping calls). `destructive` => `role=alertdialog`, red confirm button, focus starts on Cancel; otherwise `role=dialog` and focus starts on the confirm button; `typeToConfirm` adds a labelled input and keeps confirm disabled until the phrase matches (case/space-insensitive). Accessible name of the dialog = `title`; confirm button name = `confirmLabel`; testids `confirm-dialog`, `confirm-accept`, `confirm-cancel`. Works from non-React code (`lib/deleteUpcoming.ts`). |
| `toast.success/error/info(message, { action?: {label,onClick}, durationMs? })` | Shown by `ToastProvider` (main.tsx): bottom centre, above the tab bar on phones, max 3. It is a window event (`streambird:toast`), so helpers outside React can call it. | `Spinner`, `Skeleton`, `SkeletonGroup`, `PageLoader`/`BirdLoader`, `EmptyState` | spinner for inline waits; skeleton for list/card placeholders; the bird loader stays for first page loads; `EmptyState({icon,title,children,action,tone})` for "nothing here yet" and (`tone="error"`) "we couldn't load this". |

### Adding or restyling a page
1. Use `Card`/`EmptyState`/`Button`/`Input` instead of new CSS; page layout CSS goes next to the page in `index.css` (or a page-level `.css` imported by the page) using only tokens.
2. One `Button` primary per screen, destructive things `variant="danger"` after `await confirm({... destructive: true})`, async buttons `busy={saving}`.
3. Loading: `PageLoader`/`SkeletonGroup`; empty: `EmptyState`; error: `EmptyState tone="error"` or a `role=alert` line.
4. Keep every selector in the contract in `testing.md`; shortened labels keep their full `aria-label`.
5. Check 1366x800 and 390x800 (no horizontal scroll; tap targets >= 44px).
6. **Banned: `window.confirm`, `window.alert`, `window.prompt` for confirmations** (they cannot be styled, tested reliably or made accessible). Use `confirm()` / `toast`. (The brand page's file rename is now a `Modal`; the only `window.prompt` left is the studio's "Name this scene".)

## SEO: head tags, prerendered public pages, robots, sitemap (`src/seo/*`, `scripts/prerender.mjs`, backend `src/seo/seo.ts`)
- **One registry:** `src/seo/routes.ts` has the title, description and index/noindex flag of every public route (`PUBLIC_ROUTES`, `NOINDEX_ROUTES`) and `headTags()` (description, robots, Open Graph, Twitter, canonical). `components/RouteHead.tsx` (mounted in `App`) applies it on every navigation; any path not listed (signed-in app, `/join/*`, admin, 404) gets `noindex`. Titles <= 65 chars, descriptions <= 165 (a UI test enforces it).
- **Prerender:** `npm run build` (web-app) = `tsc -b && vite build && node scripts/prerender.mjs`. The script loads `src/seo/prerender-entry.tsx` through Vite's SSR loader (no browser needed, works in the Docker `web-builder` stage), renders `/`, `/privacy`, `/terms`, `/delete-account` as an anonymous visitor and writes `dist-web/_prerender/<name>.html` = the built `index.html` with the page's head tags, JSON-LD (landing only: Organization, WebSite, WebApplication; **no FAQPage/ratings on purpose**) and the markup inside `<div id="root" data-prerendered="/path">`. The origin in those files is the token `__SB_ORIGIN__`; the server swaps in `PUBLIC_BASE_URL`. The SPA is **not hydrated**: React replaces the markup on mount, and `HomeRoute` re-renders the saved markup (`lib/prerender.ts`) while the session check runs so `/` does not flash page -> spinner -> page. Page components must therefore render in Node: no `window`/`localStorage` at render time (see `detectDefaultCurrency`), and `useSyncExternalStore` needs a server snapshot.
- **Default head block** in `web-app/index.html` between `<!--seo:head-->` and `<!--/seo:head-->` is what every non-prerendered URL (app, guest links, 404) ships: description plus a basic link-preview card. Keep both markers; the prerender script replaces that block.
- **Server (`src/seo/seo.ts`, registered first in `configureApp`):** generates `/robots.txt` and `/sitemap.xml` from `PUBLIC_BASE_URL`; serves the prerendered pages (`Cache-Control: no-cache`); sends `X-Robots-Tag: noindex, nofollow` for `/api`, `/stream/*` and every app route prefix (`APP_PREFIXES`); answers **404** (with the SPA shell, which draws the 404 screen) for page URLs the SPA does not have. Files (anything with a dot in the last segment), `/health` and `/socket.io` pass through to ServeStatic. `/assets/*` (hashed) is `immutable, max-age=1y`; everything else revalidates (`app.module.ts`). `llms.txt` and `manifest.webmanifest` are plain files in `public/`.
- **robots.txt rationale:** `Disallow` only for areas behind login and never linked (`/api/`, `/dashboard`, `/streams`, `/admin`, ...). `/join/*`, `/login`, `/signup-company` stay crawlable on purpose so a crawler can read their `noindex` (a disallowed URL can still be listed without it).
- **Add a public page:** (1) route + page component in `App.tsx`/`routes/`; (2) entry in `PUBLIC_ROUTES` with a unique title/description and a `prerender` name; (3) add the page to `PAGES` in `seo/prerender-entry.tsx` and to `PUBLIC_PAGES` in `src/seo/seo.ts` (sitemap + prerender lookup); (4) add its path to `PUBLIC` in `test/ui/seo.spec.ts` and `seo.e2e-spec.ts`; (5) one `h1`, no skipped heading levels, link it from somewhere crawlable. A page that must not be indexed: list it in `NOINDEX_ROUTES` and `APP_PREFIXES`.
- **Share image:** `public/og-image.png` (1200x630, ~140 KB, 96-colour PNG). Source template `scripts/og-image.html`; regenerate by screenshotting it at 1200x630 with Playwright, then `convert og-image.png -colors 96 -strip PNG8:og-image.png` to stay under ~150 KB.
- **Images:** the brand icon in headers/loaders is `public/logo-256.png` (35 KB); `logo.png` (1704 px, 458 KB) is kept only for the canvas watermark in `studio/useHostStudio.ts`.
- **Code splitting:** only the landing, login/sign-up, legal and 404 pages are in the entry chunk; the signed-in app, guest and admin screens are `lazyPage(...)` in `App.tsx` behind one `Suspense` (entry JS 743 -> 339 kB). New signed-in pages should be lazy too.
- Tests: `test/ui/seo.spec.ts` (JS-off crawler view, head tags per route, JSON-LD, 404 status, noindex header, sitemap = canonicals, OG image size), `test/e2e/seo.e2e-spec.ts`, `src/seo/seo.spec.ts`. The audit and checklist for the founder: `docs/seo/SEO-AUDIT-2026-11.md`.

## Loading feedback (three tools — pick by situation)
| Tool | Use | Notes |
|---|---|---|
| `BirdLoader loading [compact] [label]` | a page/panel waiting on its first data | big centred bird (compact = fills the content area); stays mounted and plays a fly-out when `loading` flips false — pass the boolean, don't unmount it |
| `BirdBusy` | inside a button or status line while a user-triggered action runs | small flapping logo; keep the button label, set `disabled`; **while mounted it registers with `lib/busy.ts`** |
| `BusyOverlay` (mounted once in `main.tsx`) | automatic | shows a large centred bird + "Working on it…" whenever the busy count > 0 for 250 ms; `pointer-events: none`, so the studio stays usable |

Rules: every async button gets `{busy && <BirdBusy />}`. **The big overlay bird is for actions the user is waiting on, never for information**: in the host studio only statuses with `busy: true` (Starting publish…, Ending stream…, restoring) use it; every other status ending in `…` (a guest joining, reconnecting) gets `overlay={false}`, and each such status must be replaced when it resolves (a guest joining → "X is connected.", with a 15 s fallback). `BusyOverlay` also gives up after 45 s as a safety net. A studio status that ends in `…` is "in progress" (`isInProgress(text)`) and shows the bird; end final messages **without** `…`. For an open-ended wait the user is not blocked on (a guest alone in the room) use `<BirdBusy overlay={false} />`, otherwise the overlay would cover the page forever.

## Cookie consent (optional, off by default)
Google Analytics is **not in `index.html`**; `lib/consent.ts` injects it. The server decides the mode with `COOKIE_CONSENT_BANNER` (default `false`, served by `GET /api/config/public`, fetched by `initConsent()` in `main.tsx`):
- **off (default):** no banner, no "Cookie settings" link, analytics loads for every visitor, and `/privacy` says so.
- **on:** `components/CookieBanner.tsx` (mounted in `App.tsx`, hidden on `/join/*` and `*/studio`) shows Accept/Reject with equal weight (`.pub-cookie`); analytics loads only after Accept (choice in localStorage `streambird:consent:v1`); `CookieSettingsLink` in the landing, login and app footers reopens the banner; `/privacy` describes the opt-in. Use this for EU/UK visitors (GDPR/ePrivacy need opt-in).
If the setting can't be fetched, nothing loads. Never add another tracking/marketing script outside this module, and keep `/privacy#cookies` accurate. Playwright's `use.storageState` pre-answers the banner (Reject) for every test; the `cookie consent` tests stub `/api/config/public` to pick a mode.
